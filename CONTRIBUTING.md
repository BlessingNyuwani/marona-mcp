# Contributing

Thank you for improving the Marona MCP examples.

1. Open an issue for significant behavior or API changes.
2. Keep each language example independently runnable.
3. Add or update tests for every contract change.
4. Never commit API keys, platform tokens, or customer data.
5. Use Conventional Commit messages such as `feat:`, `fix:`, `docs:`, and `test:`.

Run the language-specific verification commands before opening a pull request.
